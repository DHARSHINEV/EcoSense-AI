# EcoSense AI – Architectural Specification

## 1. System Overview

EcoSense AI is an intelligent building energy optimizer engineered for commercial and institutional facilities. The architecture implements an end-to-end closed-loop control paradigm:

```
  ┌─────────────────────────────────────────────────────────────┐
  │                 SENSE (Multi-Zone IoT / Simulation)         │
  │   Occupancy (PIR/Vision), Temp, RH, IAQ (CO2), Power Meters │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │         PREDICT (Near-Term Demand Forecasting Engine)        │
  │   RandomForestRegressor, 1h/24h Lags, Weather, Work Schedules│
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │        OPTIMIZE (Multi-Objective Constraint Engine)         │
  │   Energy Minimization ∩ Comfort Band (22-26°C) ∩ Peak Shaving│
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │        RECOMMEND (Human-in-the-Loop Decision Interface)     │
  │   Prioritized Actions, Expected kW/₹ Savings, Status Engine │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │         MEASURE (Verification vs Fixed-Schedule Baseline)   │
  │   Verified M&V (IPMVP-aligned), Carbon Tracking, ROI Models  │
  └─────────────────────────────────────────────────────────────┘
```

## 2. Component Decomposition

### 2.1 Backend Core (`backend/app/`)
- **Simulation Subsystem (`simulation/building_sim.py`)**:
  - Deterministic physics and stochastic behavioral model.
  - Multi-zone thermal balance: solar radiation, ambient conduction, internal occupant metabolic heat (100 W/person), lighting dissipation, and plug load heat.
  - Generates reproducible time-series using fixed random seeds.
- **Baseline Engine (`simulation/baseline.py`)**:
  - Simulates conventional commercial operation: fixed 07:00–20:00 schedule on weekdays, static 22.0°C cooling setpoint, continuous 100% lighting, unmanaged peak demand.
- **Machine Learning Engine (`ml/demand_predictor.py`)**:
  - Scikit-Learn `RandomForestRegressor`.
  - Feature pipeline: chronological lag features (1-hour, 24-hour), calendar features (day of week, hour, operating flag), weather variables (ambient temperature, humidity), and zone occupancy.
  - Chronological time-series train/test split preventing temporal data leakage.
- **Optimization & Comfort Subsystem (`optimization/`)**:
  - `comfort_model.py`: Evaluates thermal comfort and bounds violations strictly during occupied hours.
  - `engine.py`: Dynamic occupancy-aware HVAC setbacks, daylight harvesting lighting dimming, predictive pre-cooling, and peak clipping algorithms.
- **State Store (`data_store/db.py`)**:
  - High-performance in-memory cache supporting real-time interactive parameter adjustments, custom scenario generation, and recommendation state transitions.
- **REST API (`api/endpoints.py`)**:
  - FastAPI router delivering typed JSON payloads validated through Pydantic schemas.

### 2.2 Frontend Client (`frontend/src/`)
- **Framework**: Next.js App Router with TypeScript.
- **Styling**: Tailwind CSS with an executive, dark-themed industrial aesthetic tailored for facility operations centers.
- **Visualization**: Recharts for dual-axis demand curves, zone load breakdowns, and occupancy correlation plots.
- **Interactivity**: Dynamic scenario switching, real-time recommendation action approvals, and financial payback modeling.

## 3. Data Integrity & Labeling Strategy

In compliance with hackathon standards:
- **`SIMULATED DATA`**: All sensor telemetry and environmental attributes generated by the deterministic simulator are explicitly labeled.
- **`MODEL PREDICTIONS`**: All machine learning regression outputs and forecast intervals are explicitly demarcated with confidence bounds and error metrics.
- **`OPTIMIZATION RECOMMENDATION`**: All advisory cards generated by the rules engine require human-in-the-loop review.
- **`SIMULATION RESULT`**: All comparative savings, carbon reductions, and peak shaving metrics reflect baseline vs. simulated optimization runs.
